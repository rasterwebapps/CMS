# 🔍 Findings Surfaced During Requirements Documentation

While reverse-engineering the SRS/BRD/FRD set in this folder (2026-09-24), the documenting agents verified every claim against the actual code rather than trusting milestone trackers or `BUSINESS_REQUIREMENTS.md` at face value. That surfaced a number of real issues — bugs, security gaps, standards violations, and stale docs — that are incidental to the documentation task itself and are collected here as a single punch list for triage. This is a findings log, not a changelog; items move to "Already fixed" once addressed, with the date and what changed.

Each item links to the module doc where it's documented in full detail.

| "Fee Finalization permission is decorative" — `FEE_FINALIZE` gates the frontend but `POST /student-fees/finalize` checks `STUDENT_FEE_MANAGE` instead | [fee-structure-collection](fee-structure-collection/FRD.md) | **Retracted 2026-09-24, on investigation to fix it.** The original claim conflated two different, similarly-named endpoints. `FeeFinalizationComponent` (route `/student-fees/finalize`, gated `FEE_FINALIZE`) actually calls `EnquiryService.finalizeFees()` → `POST /enquiries/{id}/finalize-fees`, which **is** gated `FEE_FINALIZE` on the backend — a correct match, not a mismatch. No code was changed; doing so would have broken a currently-correct gate. |
